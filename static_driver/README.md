# static_driver/

**One directory per project.** All of them are git-ignored except
[`example/`](example/), which is committed in full — three nested domains over
9 km² of Hannover, 7.6 MB of driver, built and verified. It is the worked
example and the end-to-end test in one artefact, and the place to look before
running anything.

 Everything about one static driver — how it was
asked for, what went into it, what came out and what it cost — lives under
`static_driver/<run>/` and nowhere else.

Not versioned. A driver set is hundreds of megabytes to several gigabytes, the
working directory beside it is tens of gigabytes, and all of it is reproducible
from `config/<run>.yml`. What is *not* reproducible is the reasoning, so that
goes into `docs/README.md` in writing.

```
static_driver/<run>/
├── <run>_static              root domain     ← PALM reads exactly this name
├── <run>_static_N02 …        the nests       ← the suffix is what marks a nest
│
├── config/                   what was asked for
│   ├── <run>.yml                 the run configuration
│   ├── <run>_layout.yml          optional: PALM domain names and PE budget
│   ├── <run>_static_csd.yml      the palm_csd configuration, generated
│   ├── sources_<rr>.yml          a RECORD of the region files that were used,
│   ├── mapping_<rr>.yml            copied here by finalize.py — not an input
│   └── <run>_p3d[r][_N0x]        PALM namelists, if update_p3d.py was used
│
├── products/<domain>/*.tif   what palm_csd was given (+ manifest.json, trees.gpkg)
│
├── docs/
│   ├── <run>_static*.pdf         palm_csd --pdf, one sheet per domain
│   ├── DATA-SOURCES.md           generated by the `sources` stage: what this
│   │                               driver is built from and what that permits
│   └── README.md                 what this run is and on what data it rests
│
└── work/                     what it cost — intermediates, deletable
    ├── state.json                the plan: tiers, tiles, chosen ortho epochs
    ├── vector/*.gpkg             cadastre, footprints, bridges, roads, trees
    ├── tiers/<tier>/             per-tile rasters and the composed classification
    │   ├── tiles/<x>_<y>/            zt, ndsm, ndvi (leaf-on/leaf-off), ortho
    │   ├── surface/<x>_<y>/          the composed PALM class of every pixel
    │   └── vrt/*.vrt                 virtual mosaics, read by the domains stage
    └── inspect/                  QGIS control layers with the full class legend
```

The project name comes from `project.name` in the run config and must end in
`_static`, because PALM reads the root domain's driver as `<jobname>_static`.
palm_csd writes the root as `<run>_static_root`; `tools/finalize.py` drops that
suffix, since the suffix is what identifies a *nest*.

## Building one

From the project root — the directory holding `repository/`:

```bash
export PYTHONPATH=repository
CFG=static_driver/<run>/config/<run>.yml

python -m palmgeo.cli sources $CFG            # what exists, under what licence
python -m palmgeo.cli sources $CFG --approve  # accept it; unlocks the downloads
python -m palmgeo.cli all     $CFG
MPLBACKEND=Agg env -u PROJ_DATA -u PROJ_LIB palm_csd --pdf static_driver/<run>/config/<run>_static_csd.yml
python repository/tools/finalize.py            $CFG   # into final shape
python repository/tools/verify_driver.py       $CFG   # structure — must PASS
python repository/tools/check_classification.py $CFG  # plausibility
```

`verify_driver.py` proves the driver is *structurally* sound; it cannot tell you
the classification is *right*, because a uniformly wrong map is structurally
perfect. Run `check_classification.py` as well.

## Starting a new project

The template is preset for the Lower Saxony reference region; for any other
region change the keys its header lists under THE REGION.

```bash
mkdir -p static_driver/<run>/config
cp repository/config/template.yml static_driver/<run>/config/<run>.yml
$EDITOR static_driver/<run>/config/<run>.yml   # replace every `myrun`,
                                               # set the region,
                                               # rewrite `domains:`
export PYTHONPATH=repository
python -m palmgeo.cli plan static_driver/<run>/config/<run>.yml
```

To run the derivation somewhere without a network, either carry `work/` to that
machine — everything after `rasters` needs nothing else — or fetch every source
first and set `runtime.offline: true`:

```bash
python -m palmgeo.cli fetch $CFG --check   # what a fully offline run would need
python -m palmgeo.cli fetch $CFG           # needs runtime.keep_downloads: true
```

`sources` and `plan` both do no bulk I/O. `sources` prints what data exists
over the area, its licence and what each dataset becomes; `plan` prints the
domains, the work tiers, the orthophoto epochs it would choose and the volume
it would transfer. Read both before committing a weekend of downloads to a grid
that turns out to be misaligned or to data you may not use.

## Size and cleaning

Roughly **20 MB per km² at 1 m**, a tenth of that at 4 m, so a city-scale run
wants 50–100 GB. `project.workdir` defaults to `static_driver/<run>/work` and
accepts an absolute path — point it at another disk if this one is tight.

Every tile directory carries a `.done` marker holding a fingerprint of the
settings that stage actually reads, so an interrupted run resumes and a changed
threshold invalidates exactly the tiles that depended on it. The composition
also hashes the vector layers it reads, so re-running `vectors` or `buildings`
recomposes. Deleting a marker forces that tile to be rebuilt.

```bash
python -m palmgeo.cli clean $CFG work      # all of it
python -m palmgeo.cli clean $CFG surface   # only the composition, keeping the
#   expensive downloaded and derived tiles. This is what a code change calls
#   for; a config change invalidates itself.
```

`clean work` removes the derived directories, not the configuration.

## Write the project README

Into `docs/README.md`, for every run. The driver itself records none of this,
and nobody — including you in six months — can reconstruct it from the NetCDF.

**Start with the standard header block.** Whoever receives a driver has three
questions before any others: what is this, may I use it, and what should I not
trust. The block answers them in the same place in every project, so nobody has
to hunt:

```markdown
# <Place> — PALM static driver

| | |
|---|---|
| **Domains** | `root` 2048×2048 @ 16 m<br>`N02` 2048×2048 @ 4 m, parent `root` |
| **Region** | `NI`, EPSG:25832 |
| **Built** | 2026-09-08, 399 MB, palmgeo 1.2.0 |
| **Data basis** | `dgm1`, `dom1`, `dop20`, `alkis`, `lod2`, `bdlm` |
| **Licences** | dl-de-by-2.0 — see [`DATA-SOURCES.md`](DATA-SOURCES.md) |

**What you may do with it.** <the conclusion, in a sentence>

**What you need to know.**

* <the two or three caveats that would change somebody's mind>
```

Every field comes from something already recorded — the domains from the run
config, the licences and obligations from `state.json`, the size and date from
the driver file. The **Licences** row points at `DATA-SOURCES.md` rather than
restating it, so the two cannot disagree; what the header adds is the
*conclusion*, which the generated file deliberately does not draw for you.

Below the block, write freely: what was built, what was dropped, what was
assumed, and what you checked. That part is the reason the file exists.

**Be specific about weakness.** A caveat like "the terrain is coarse" helps
nobody. "FABDEM sits above the surface model across a third of the domain, so
there are no measured object heights there" tells the next person exactly which
results to distrust. The NetCDF records none of it,
and nobody — including you in six months — can reconstruct it from the file.
